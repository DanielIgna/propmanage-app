# PPOS-003 · UX Psychology
Status: Draft v1.0 · Owner: Product Council
Legile aplicate cu exemple REALE din auditul PropManage (dovezi în `/app/docs/PRODUCT_AUDIT_PPOS_2026.md`).

| Lege | Ce spune | Aplicare PropManage (exemplu din audit) |
|---|---|---|
| Hick's Law | timpul de decizie crește cu numărul opțiunilor | Client activ avea 3 CTA-uri primare (Plătește/Solicită/Vreau ofertă) → rămâne UNUL |
| Miller's Law | 7±2 elemente în memoria de lucru | Property Hub avea 10+ carduri de rang egal → 1 scor + 3 secțiuni |
| Nielsen #1 (vizibilitatea stării) | sistemul spune mereu adevărul despre stare | „Configurare 0/6" la cont configurat = încălcare directă → progres derivat din date |
| Nielsen #8 (minimalism estetic) | fără informație irelevantă | 9 unelte blocate listate → ascunse, 1 rând „următoarea deblocare" |
| Progressive Disclosure | dezvăluie complexitatea treptat | matricea J0→P client, ENTRY→TOP specialist (PPOS-007) |
| Fitts's Law | ținte mari, aproape | CTA primar hero mare; touch ≥44px; cookie banner nu fură cel mai bun plasament |
| Gestalt (proximitate/similaritate) | grupare vizuală = grupare logică | badge-urile de trust grupate, max 2 pe card public |
| Recognition over Recall | recunoaștere, nu memorare | navigație stabilă 4 tab-uri; fără rute-fantomă; etichete umane, nu jargon |
| Cognitive Load Theory | sarcina extrinsecă se minimizează | overlay-urile simultane (tur+cookie+feedback+chat) → un singur element plutitor |
| Peak-End Rule | finalul definește amintirea | momente de celebrare la primul document/prima lucrare (există — se păstrează) |
| Jakob's Law | userii vin cu așteptări din alte produse | desktop = pattern Stripe/Linear (workspace), nu landing page |
