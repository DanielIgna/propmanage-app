# GI-5P — PROPERTY INTELLIGENCE LAYER (Document Strategic, 25 Iul 2026)
GI-4 & GI-5 FROZEN. Zero cod/DB. Perspectivă: cum învață PROPRIETATEA (Twin = produsul).

## Întrebarea fundamentală — răspuns
Twin viu = proprietatea știe: 1) CE SUNT (DNA) 2) CE MI S-A ÎNTÂMPLAT (Timeline+Memory)
3) CUM MĂ SIMT (Health) 4) CE MĂ AMENINȚĂ / CE URMEAZĂ (Risk+Predictive) 5) CÂT VALOREZ (Value+Maturity).
Principiu suprem: provenance-first — niciun atribut fără sursă+confidence+dovadă, niciun scor fără „de ce".

## Cele 13 componente (detalii complete în raportul din chat)
1. Property Memory — experiențe structurate (nu doar documente): tehnice/economice/oameni/mediu
   + comportamentul proprietarului. MVP.
2. Property DNA v2 — stratificat (Identitate/Structură/Anvelopă/Sisteme/Interior/Echipamente/
   Context/Particularități/Istoric modificări), fiecare atribut {valoare,sursă,confidence,verificat_la}.
   Auditul Tehnic = mecanismul comercial de upgrade confidence. MVP: straturi critice.
3. Property Timeline — fir cronologic unic append-only, contract unic de citire peste sursele
   existente (DNA timeline, pvi_history, warranties). MVP.
4. Property Knowledge — fapte derivate cu dovezi din audituri/lucrări/defecte/costuri/uzură +
   Maintenance Discipline Score (comportament proprietar → prioritizare Revenue Hunter).
5. Property Health Engine — componente 0-100 cu ponderi, DECAY temporal determinist fără
   întreținere dovedită, creștere doar prin evenimente dovedite (bounded existent), health_history.
6. Property Risk Engine — risc=probabilitate×impact pe 6 categorii (tehnic/financiar/juridic/
   operațional/întreținere/degradare), fiecare risc cu dovezi + mitigare = serviciu marketplace.
7. Predictive Maintenance FĂRĂ ML — metoda actuarială: bibliotecă de referință (durate viață/
   revizii per activ, statică, versionată) × vârsta reală × modulatori (incidente, revizii, context)
   → EOL ± incertitudine + cost din prețurile reale marketplace. ML = doar rafinare Future.
8. Asset Lifecycle — registru PropertyAsset {instalat_la, garanție→warranties, intervenții→timeline,
   EOL→§7}; la înlocuire noul activ moștenește slotul, istoricul rămâne.
9. Property Knowledge Graph — noduri (Property/Zone/Asset/Person/Document/Event/Risk/Service/
   Warranty/Lesson) + muchii tipizate; evoluție în 3 trepte fără redesign: referințe id (MVP) →
   API traversare (Sprint) → graph store (Future, doar la volum).
10. Explainability — orice scor: componente + formulă versionată + dovezi (id-uri timeline) +
    surse; fără date → explicit „Ipoteză — cere audit".
11. Property Learning Loop — generalizarea Value Loop la ORICE eveniment de viață:
    extrage→înregistrează→actualizează active→recalculează scoruri→generează riscuri/recomandări.
12. Property Value Intelligence — PVI neschimbat (documentare) + Technical Condition Index +
    Investment Index (nou) + Commercial Value Context (Future, cere GI-6). Niciun index ≠ preț piață.
    Împreună = „dosarul de valoare" (Carfax-ul casei).
13. Digital Twin Maturity Score — L0 Înregistrată → L1 Identificată → L2 Documentată (PVI≥40) →
    L3 Activă (timeline viu) → L4 Monitorizată (audit<24 luni) → L5 Predictivă (EOL+riscuri complete).
    Criterii binare; fiecare treaptă lipsă = ofertă comercială; Maturity mediu = KPI Mission Control.

## Separare etape
MVP: DNA v2 straturi critice, Timeline unificat, registru active majore, Health decay+history,
Predictive actuarial (centrală/electric/acoperiș/termopane), Risk tehnic+întreținere+juridic,
Maturity L0-L5. Sprint: DNA complet, graph API, risc financiar, indices noi, Discipline Score.
Future: senzori IoT, graph store, ML actuarial, Commercial Value Context, Twin 3D, dosar exportabil.
