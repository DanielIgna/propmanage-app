## Reguli permanente instituite
1. „PM-110 este aprobat. Implementează integral funcționalitatea. Creează schema bazei de date, API-urile, interfața, notificările și testele. Consideră documentul doar specificația. Rezultatul final trebuie să fie cod funcțional, nu documentație suplimentară."
2. „Orice document PPOS marcat ca APPROVED și clasificat ca Growth Engine sau Core Feature trebuie transformat în cod. Nu crea documente suplimentare decât dacă sunt necesare pentru implementare."
3. „Orice document care poate genera utilizatori, tranzacții sau venituri trece din starea Design în starea Implementation Now."
4. „Nicio funcționalitate nouă nu are prioritate peste una care poate genera utilizatori, specialiști, tranzacții sau venituri."

## GBOS v1.0 — ordinea de implementare constituțională
1 Growth · 2 Revenue · 3 Trust · 4 Retention · 5 Infrastructure.
Un document e COMPLET doar când: DB + Backend + API + Frontend + Mobile + Notificări + Analytics + Teste + Deploy există.
Growth Rule: „What valuable action does this create next?" — NONE ⇒ postpone.
Revenue Rule: fiecare sprint mișcă ≥1 KPI (owners/specialists/requests/jobs/revenue/trust/twins), altfel sprintul a eșuat.
Marketplace Rule: vizibilitatea se câștigă (jobs, verified reviews, would hire again, recommend, trust, verificare, portofoliu) — nu se cumpără.
AI Directive: stop documentație când implementarea e posibilă; documentele aprobate = specificații; production-ready, incremental, testat continuu.
Succes = owners, specialists, jobs, twins, recommendations, would-hire-again %, trust, revenue — nu pagini de documentație.
