One professional — Many capabilities — Many services — Many projects — Many partnerships. END

## MISIUNE — RESPONSIBILITY LEVELS (VERBATIM)

MISSION
Every project must clearly define who is responsible for each stage.
No professional may claim services that are not part of their verified capabilities.
The customer must always know: Who designs. Who validates. Who executes. Who verifies. Who guarantees. Who maintains.

Each service has one of four responsibility levels:
- **LEAD** — owns the complete delivery. Responsible for quality, communication, deadlines, deliverables.
- **CO-PARTNER** — works together with another Lead. Provides specialized expertise. Cannot close the stage alone.
- **SUPPORT** — provides technical assistance. Completes specific tasks. No direct responsibility for final delivery.
- **CONSULTANT** — provides recommendations only. No execution. No delivery responsibility.

Every capability receives one responsibility level. Examples:
- AUDIT: PropManage LEAD · Designer SUPPORT
- DIGITAL TWIN: PropManage LEAD · Designer CO-PARTNER · Architect CO-PARTNER
- 3D MODEL: Designer LEAD · PropManage SUPPORT
- TECHNICAL INSTALLATION MAPPING: PropManage LEAD · Engineer CO-PARTNER · Designer SUPPORT
- INTERIOR DESIGN: Designer LEAD · PropManage SUPPORT
- IMPLEMENTATION: Project Manager LEAD · Designer CO-PARTNER · PropManage CO-PARTNER
- HOUSE HEALTH: PropManage LEAD · Designer CONSULTANT

The platform automatically generates Responsibility Matrix for every project. Customers always know who is responsible for every deliverable. END

## MISIUNE — DUAL TRACK EXECUTION (VERBATIM)

MISSION
PropManage enters Dual Track Execution. The platform evolves simultaneously on two independent tracks.

**TRACK A — GO LIVE.** Priority: Production / Beta / Stability / Performance / Security / Payments / Analytics / Customer Onboarding / Specialist Onboarding / Bug Fixes / Quality Gates / Real Customer Feedback. **This track has absolute priority. Nothing may delay production readiness.**

**TRACK B — ECOSYSTEM FOUNDATION.** Build reusable infrastructure without affecting production. Examples: Professional Operating System / Designer Ecosystem / Capability Engine / Portfolio Engine / Knowledge Graph foundations / Company Twin foundations / AI Matching foundations / Role Permissions / Professional Digital Twin / Relationship Engine. These modules remain modular. They must not slow down Track A.

DEVELOPMENT RULE: Every task must be assigned to Track A or Track B. Never mix priorities. Production always wins. Architecture grows in parallel.

SUCCESS: Track A creates customers. Track B creates the future. Both advance every sprint. END

## MISIUNE — ECOSYSTEM COMPATIBILITY EVALUATION (VERBATIM)

MISSION
While PropManage is preparing for public launch, every new module must be evaluated for future ecosystem compatibility.
Before implementing any feature ask: Can this support multiple professionals? Multiple companies? Multiple services? Can it connect to Digital Twin? Can it become reusable? Can another industry reuse it?
If YES — design it as reusable infrastructure. If NO — keep it simple for MVP but never block future expansion.
**MVP FIRST. Architecture SECOND. Scalability ALWAYS.** END
